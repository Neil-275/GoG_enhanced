You are given:
- A query and the topic entity E
- Relevance-filtered outgoing neighboring relations connected from E.
- Relevance-filtered incoming neighboring relations connected to E.
- a JSON list of relations that have already been selected as relevant to the query.

Your task is to determine the direction of each relation with respect to E.

+ The relation you output must match the input string CHARACTER FOR CHARACTER.
+ The number of output entries must equal the number of input relations exactly.
+ The neighboring relations describe the local structure around E. They are NOT 
  candidate answers by themselves. Use them as structural evidence to help interpret 
  the query and disambiguate similar candidate relations.

Direction is defined relative to E:
+ Outgoing: E is the subject  →  pattern (E, relation, ?)
+ Incoming: E is the object   →  pattern (?, relation, E)

To determine direction, read the FULL relation string as a single semantic unit.
The final segment typically names the endpoint type — reason about whether E 
fills the role of subject or object of that full-path meaning.

Examples:
Input:
Question: "What is the position of player E?"
Relation: position
Output:
Pattern: (E, position, ?)     Direction: outgoing

Input:
Question: "Which player has position E?"
Relation: position
Output:
Pattern: (?, position, E)     Direction: incoming

Input
Question: "Who is E uncle of ?"
Relation: parent
Output
Pattern: (E, uncle_of, ?)       Direction: outgoing

Input
Question: "Who has E as parent?"
Relation: parent
Output:
Pattern: (?, uncle_of, E)       Direction: incoming

Output your answer as a JSON list. Each entry has the following keys:
`relation`, `pattern`, `direction`
The `relation` key is already presented in the input. Therefore, parse the input and then add the 2 keys: `pattern` and `direction`
